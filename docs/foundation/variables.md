# 第 06 讲 · 变量、常量、iota 与作用域

> 第 05 讲建立了"值、变量、类型"的模型，这一讲把"怎么写出来"补齐。声明有几种写法、没赋值时变量里是什么、不变的量怎么表达、一组枚举怎么自动编号、名字在多大范围内可见——这些是写每一行代码都要用到的基础。它们看起来琐碎，却恰恰是零基础最容易 silently 出错的地方：一个不小心，改到的就不是你以为的那个变量。

## 1. 先建立直觉

继续用厨房类比：声明变量就是领一个贴好标签的盒子；零值是盒子出厂时自带的默认内容，所以 Go 里领了盒子就能用，不存在"忘了初始化"的空洞；常量是封死不许再改的盒子；`iota` 是给一整排盒子自动贴流水号的机器，你只写第一张，后面依次加一；作用域则是"这个盒子在哪个区域能被看见"——出了那扇门，名字就不认识了。

<ConceptDiagram type="stack-heap" title="作用域决定变量在哪可见、活多久" />

图上把"随函数调用分配、随栈帧结束回收的局部变量"和"生命周期更长、由垃圾回收管理的对象"分开摆。先借它建立一个印象：声明位置不同，变量的可见范围与存活时间就不同。至于具体谁在栈、谁在堆，由编译器的逃逸分析决定，那是第 09 讲的内容；本讲只关注"名字在哪能被看见"。

## 2. 语法与规则

声明有两种主力写法。完整写法用 `var`，可以只声明不赋值，此时变量自动拿到<Term word="零值" text="变量只声明未赋值时的默认值：数值为 0、字符串为空串、布尔为 false、引用类为 nil。" />：

```go
package main

import "fmt"

func main() {
	var count int          // 只声明，拿到零值 0
	var name string        // 零值是空字符串
	price := 12            // 短声明加推断，等价于 var price int = 12
	fmt.Println(count, name == "", price)
	fmt.Printf("%T %T %T\n", count, name, price)
}
```

<OutputBox title="运行结果" output="0 true 12\nint string int" />

短声明 `:=` 只能在函数内部用，左边至少要有一个**新**变量，否则应该用赋值 `=`。包级变量必须老老实实写 `var`。

| 对比项 | var 完整声明 | := 短声明 |
| --- | --- | --- |
| 可用位置 | 包级、函数内都可以 | 只能在函数内 |
| 是否写类型 | 可写也可省略 | 不写，由右值推断 |
| 能否只声明 | 能，得到零值 | 不能，必须带初值 |
| 左侧全已声明 | 不适用 | 编译报错，应改用赋值 |
| 典型用法 | 包级变量、需要先零值 | 函数内绝大多数局部变量 |

常量用 `const`，一旦声明不能被重新赋值。`iota` 只在 `const` 组里生效，从 0 开始每换一行自动加一；省略表达式的行会沿用上一行的写法，非常适合给一组相关的量自动编号：

```go
package main

import "fmt"

// iota 从 0 起每行加 1；省略表达式的行会重复上一行的写法
const (
	Monday = iota + 1 // 1
	Tuesday           // 2
	Wednesday         // 3
	_ = iota + 1      // 用空标识符跳过编号 4
	Friday            // 5
)

// 表达式也能复用：这里的 1 << (10 * iota) 会被下面两行沿用
const (
	KB = 1 << (10 * iota) // 1
	MB                    // 1024
	GB                    // 1048576
)

func main() {
	fmt.Println(Monday, Tuesday, Wednesday, Friday)
	fmt.Println(KB, MB, GB)
}
```

<OutputBox title="运行结果" output="1 2 3 5\n1 1024 1048576" guess="true" />

第二组常量是工程里很常见的写法：单位换算的倍率用 `iota` 加移位一次生成，比手写三个魔法数字更不容易错，第 12 讲的单位换算器会用到同样的思路。

第三段代码是本讲最该亲手跑一遍的：作用域与遮蔽。

```go
package main

import "fmt"

var total = 100 // 包级变量，首字母小写，只在本包可见

func main() {
	fmt.Println("外层：", total)
	{
		total := 5 // 块内短声明，遮蔽了外层的同名变量
		fmt.Println("块内：", total)
	}
	fmt.Println("回到外层：", total)
}
```

<LineByLine code="var total = 100\nfunc main() {\n    total := 5\n    fmt.Println(total)\n}" :notes='["包级变量在整个包内可见，首字母小写表示不对外导出","进入 main 函数，开始一个新的作用域","块内又声明了同名变量，它是全新的一个，不是给外层赋值","这里打印的是内层那一份，外层那个 total 全程没被碰过"]' />

<OutputBox title="运行结果" output="外层： 100\n块内： 5\n回到外层： 100" guess="true" />

花括号会开出一个新的<Term word="作用域" text="名字生效的代码范围；内层作用域可以声明同名变量遮蔽外层的那一个。" />。内层用 `:=` 声明了同名的 `total`，于是它**遮蔽**（shadow）了外层的变量：块内改的是新盒子，出了块，外层的 100 原封不动。这不是 bug，但极容易在 `if`、`for` 里被忽略，排查时看着"明明赋值了却没生效"。

## 3. 深入一步

常见类型的零值记一张表就够了：

| 类型 | 零值 | 说明 |
| --- | --- | --- |
| int / float64 | 0 | 数值一律归零 |
| string | 空字符串 | 不是 nil，可直接拼接 |
| bool | false | 条件判断的默认值 |
| 指针 / 切片 / map / 接口 | nil | 表示尚未指向任何东西 |

<Term word="导出" text="包级标识符首字母大写即可被其他包访问；小写则只在包内可见，Go 没有 public 关键字。" />

<Callout type="warn" title="四个高频编译错误" text="第一，:= 左边若全是已声明的变量，编译器会报 no new variables，改用 = 即可。第二，:= 不能写在函数外，包级声明必须用 var 或 const。第三，函数内声明的局部变量若一次都没被使用，是编译错误（呼应第 03 讲），包级变量则不受此限制。第四，别把遮蔽当成赋值：if 里写 x := 1 往往只是造了个新变量，外面的 x 并没有变。" />

## 4. 工程实践

几条能立刻用上的经验。第一，函数内局部变量优先用 `:=`，简洁且把类型交给编译器；但一旦涉及 `if err != nil` 这类分支，留意别意外遮蔽外层的 `err`。第二，任何"不该被改"的量都用 `const` 表达，让约束由编译器守着，而不是靠注释提醒。`iota` 只用于**一组彼此相关**的枚举或倍率，硬把不相干的常量凑进一个组，反而让后来者看不懂编号含义。第三，包级变量要非常克制：它是全局状态，会让单元测试互相污染，也让初始化顺序变成隐患（阶段三讲 `init` 时会再展开）。

命名上也有 Go 自己的习惯：短作用域用短名字（`i`、`n`、`err`），作用域越大名字越要完整；用驼峰而不是下划线；常见缩写保持一致的大写，如 `HTTPServer`、`userID`。首字母大小写同时承担可见性，所以命名不只是好看，它直接决定这个标识符能不能被别的包用。

<Callout type="tip" title="一个排查技巧" text="遇到变量赋值后好像没生效，先沿着花括号往外看一遍：是不是在某层里用 := 又声明了同名变量。这类问题 go vet 的 shadow 相关检查能帮一部分忙，但根本办法还是让作用域尽量小、名字尽量不重复。" />

## 小结与下一讲

- `var` 与 `:=` 各有位置限制；零值保证声明即可用，避免未初始化崩溃。
- `const` 加 `iota` 让一组相关常量自动编号，表达式可沿用，魔法数字因此变少。
- 作用域由花括号划分，内层同名声明会遮蔽外层；命名大小写决定跨包可见性。
