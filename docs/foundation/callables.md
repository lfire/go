# 第 10 讲 · 函数、多返回值、变参与闭包

> 前面每一讲都在写 `main`，但真正让代码可复用、可组合的是函数。Go 的函数有几个和别的语言不太一样的地方：一次能返回多个值（错误处理的基石）、函数本身可以当值传来传去、内部函数能记住外层的变量，还有一条"下班前一定做"的 `defer`。这一讲把这些拼图补齐，地基阶段就此收口。

## 1. 先建立直觉

把函数想成一台贴了说明书的机器：有输入口（参数）、输出口（返回值）和内部流程（函数体）。Go 的机器比常见语言多几样本事：输出口可以不止一个（多返回值）；整台机器可以当零件交给另一台机器（函数作为值）；机器出厂时还能随身带上车间里的某样东西并一直记住它（闭包）；另外可以登记一张"下班前务必执行"的清单（`defer`）。

<ConceptDiagram type="stack-heap" title="函数调用开栈帧，闭包捕获的变量要活得更久" />

闭包这件事正好用第 09 讲的内存模型解释：外层函数的局部变量本该随栈帧一起回收，可一旦被内部函数引用，编译器就会让它<Term word="逃逸" text="变量需要活过当前函数时，编译器把它分配到堆上，由 GC 负责回收。" />到堆上，于是闭包每次调用都能读改同一份状态。理解了这个，"函数为什么能记住东西"就不是魔法了。

<ConceptDiagram type="defer-stack" title="defer 登记的语句按后进先出，在函数返回前执行" />

## 2. 语法与规则

先看 Go 最常见的函数形态：一次返回两个值，结果在前、错误在后。

```go
package main

import (
	"errors"
	"fmt"
)

func divide(a int, b int) (int, error) { // 结果在前，错误在后
	if b == 0 {
		return 0, errors.New("除数不能为零")
	}
	return a / b, nil
}

func main() {
	q, err := divide(42, 2)
	if err != nil {
		fmt.Println("出错了")
		return
	}
	fmt.Println("商：", q)
	q2, _ := divide(10, 3) // 用空标识符忽略不需要的值
	fmt.Println("只取商：", q2)
}
```

<OutputBox title="运行结果" output="商： 21\n只取商： 3" guess="true" />

返回多个值时，调用方必须用同等数量的变量接住；不想要的用 `_` 丢掉。把错误放在最后一个返回值是 Go 全生态的惯例，第 20 讲会系统展开错误处理，这里只需要看懂"函数能一次给出结果和它的状态"这件事。返回值也可以命名，写成 `(q int, err error)`，配合裸 `return` 使用，但工程上要谨慎，后面会讲原因。

第二段看变参与"函数作为值"：

```go
package main

import "fmt"

func sum(nums ...int) int { // 变参：调用时可以给任意多个 int
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func apply(f func(int) int, x int) int { // 函数本身也能当参数
	return f(x)
}

func double(n int) int { return n * 2 }

func main() {
	fmt.Println("求和：", sum(1, 2, 3, 4))
	fmt.Println("把函数传进去：", apply(double, 21))
}
```

<LineByLine code="func sum(nums ...int) int {\n    total := 0\n    for _, n := range nums {\n        total += n\n    }\n    return total\n}" :notes='["三个点表示变参，函数内部把它当成一个序列来用","先准备一个累加用的变量，初始为零","逐个取出序列里的元素并累加","循环结束返回总和"]' />

<OutputBox title="运行结果" output="求和： 10\n把函数传进去： 42" />

变参必须是参数列表的**最后一个**，函数内部可以用 `range` 遍历、用 `len` 数个数；手里已有序列时，用 `sum(序列...)` 把它展开传入。`apply` 的签名里 `func(int) int` 是一种<Term word="函数类型" text="由参数与返回值决定的类型；同签名的函数可以赋给同一个变量或作为参数传递。" />，只要签名一致，任何函数都能传进去——这就是回调与策略模式的底座。

第三段把闭包与 `defer` 放在一起看：

```go
package main

import "fmt"

func counter() func() int { // 返回值本身是一个函数
	n := 0
	return func() int { // 匿名函数捕获了外层的 n
		n++
		return n
	}
}

func main() {
	next := counter()
	fmt.Println(next(), next(), next())
	defer fmt.Println("这句最后才执行")
	fmt.Println("正常流程")
}
```

<OutputBox title="运行结果" output="1 2 3\n正常流程\n这句最后才执行" guess="true" />

`counter` 返回的匿名函数带着外层的 `n` 一起活了下来，所以三次调用依次得到 1、2、3。`defer` 则把一条语句登记起来，等当前函数**即将返回时**才执行，因此"正常流程"先打印、被 defer 的那句最后打印。多个 defer 按后进先出的顺序执行，最常见的用途是配对清理资源，第 21 讲会完整展开。

## 3. 深入一步

| 写法 | 形态 | 适用 |
| --- | --- | --- |
| `func f(a int) int` | 单返回值 | 纯计算 |
| `func f(a int) (int, error)` | 多返回值 | 可能失败的操作，Go 最常见 |
| `func f(nums ...int) int` | 变参 | 参数个数不固定 |
| `f := func(x int) int {...}` | 函数字面量赋给变量 | 回调、临时逻辑 |
| `func f() func() int` | 返回函数 | 闭包、带状态的生成器 |

<Callout type="warn" title="版本差异与四个坑" text="第一，闭包捕获的是变量本身而不是当时的值；在循环里创建闭包尤其容易出错，Go 1.22 起把每次迭代的循环变量改成独立声明，老版本代码行为不同，第 15 讲专门拆解。第二，命名返回值配合裸 return 看似省事，却容易和内层同名变量遮蔽搅在一起，可读性差，短函数里尤其不推荐。第三，defer 的参数在声明那一行就求值，不是执行时。第四，在大循环里 defer 会一直堆积到函数结束才执行，可能拖住文件句柄等资源，应放进小函数或手动关闭。" />

## 4. 工程实践

写 Go 风格函数，有几条几乎不会错的默认。签名要短：参数超过四五个就该想想是不是该用一个结构体收拢（阶段二讲结构体）。可能失败的操作一律返回 `(结果, error)`，且错误永远放最后，调用方第一件事就是判错，别把错误和其它返回值混在一起。返回值要不要命名？短函数用普通 `return` 最清楚，命名返回只在"多个返回点、需要在 defer 里修正返回值"这类确有收益的场景才用。

闭包很方便，但要留意它把外层变量的生命周期拉长了：捕获一个大对象会让整块内存跟着闭包一起存活，别在闭包里顺手抓了整个请求上下文。函数作为值最适合做回调、排序比较、策略切换——签名一致就能替换，比塞一堆布尔开关清爽。

`defer` 的工程价值在"打开与关闭写在一起"：拿到文件、锁、连接后立刻 `defer` 关闭，后续无论从哪个分支返回都不会漏。但要记住它作用范围是**当前函数**，所以循环里处理一批资源时，最好把单次处理拆成小函数，让 defer 在每次调用结束就生效，而不是攒到最外层函数才执行。

<Callout type="tip" title="一条诊断线索" text="如果某个闭包里的值怎么都不对，先回头看它是在循环里创建的吗、捕获的是变量还是当时的副本。配合第 09 讲的栈帧模型想一遍：被捕获的变量不在原栈帧里，而是在堆上被多次调用共享，问题往往就出在这里。" />

## 小结与下一讲

- 多返回值是 Go 的核心惯例，`(结果, error)` 让失败显式可见；命名返回要克制使用。
- 变参、函数作为值、闭包让代码能组合出回调与带状态的行为，背后是第 09 讲的栈帧与逃逸。
- `defer` 在返回前按后进先出执行，配对清理资源时最有用，但要避开循环堆积与参数求值时机。
