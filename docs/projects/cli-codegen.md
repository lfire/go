# 第 104 讲 · 实战 02 · protoc 插件与代码生成器

> 错误码注册表、枚举的 String、protobuf 的 .pb.go 有个共同点：结构重复、错一个就编译不过。代码生成把正确性交给一份可测输入与一段模板，定义改了产物必然同步改，且编译器替你验收。本讲全程标准库即可运行。

## 1. 项目目标与约束

| 维度 | 目标 | 约束 |
| --- | --- | --- |
| 输入 | 一份错误码定义 | 解析失败必须报错 |
| 产物 | 可编译的注册表 | 头部标记 DO NOT EDIT |
| 正确性 | 通过 go build | 渲染后强制 go/format 体检 |
| 可重复 | 重跑无意义 diff 为零 | 内容未变则不写盘 |

**protoc 插件是独立可执行程序**：从标准输入读 CodeGeneratorRequest，把源文件塞进 CodeGeneratorResponse 写回标准输出，protoc 负责调度；Go 侧用 protogen 与 protoreflect 免去底层编解码。插件只是触发器，真正决定质量的是解析描述、建模、模板、格式化、落盘这条流水线；换成 protoc 输入只替换第一步。

<Callout type="tip" title="为什么生成而不是反射" text="反射拼错要等运行到那行才暴露；生成的代码被编译器检查、IDE 可跳转，把校验提前到编译期是最硬的理由。" />

## 2. 架构蓝图

<ConceptDiagram type="compile-link" title="从定义到可编译产物" caption="定义先解析成中间模型，模板只依赖模型；格式化兼做排版与语法校验，落盘前比对内容" />

关键是中间模型：模板不许直接读语法树，否则输入格式一变就到处 panic。抽出 ErrCode 后解析层与渲染层可各自演进。五步各做一件事，失败都能精确定位：读不到是输入问题、断言失败是解析问题、渲染报错是模板问题、format 报错是产物语法问题。

## 3. 关键模块实现

### 3.1 解析层：用 go/ast 安全抽取定义

```go
package main

import (
	"fmt"
	"go/ast"
	"go/parser"
	"go/token"
	"os"
	"path/filepath"
	"strconv"
)

// ErrCode 是中间模型；模板只认识这两个字段。
type ErrCode struct {
	Name  string
	Value int
	Doc   string
}

// ParseCodes 解析一个 Go 源文件，收集 const 声明里的整数常量。
func ParseCodes(filename string) ([]ErrCode, error) {
	fset := token.NewFileSet()
	f, err := parser.ParseFile(fset, filename, nil, parser.ParseComments)
	if err != nil {
		return nil, fmt.Errorf("解析 %s: %w", filename, err)
	}
	var codes []ErrCode
	ast.Inspect(f, func(n ast.Node) bool {
		gd, ok := n.(*ast.GenDecl)
		if !ok || gd.Tok != token.CONST {
			return true // 不是 const 块，继续往下遍历
		}
		doc := ""
		if gd.Doc != nil {
			doc = gd.Doc.Text()
		}
		for _, spec := range gd.Specs {
			vs, ok := spec.(*ast.ValueSpec)
			if !ok {
				continue
			}
			for i, name := range vs.Names {
				if i >= len(vs.Values) {
					continue // 隐式继承上一行，跳过
				}
				lit, ok := vs.Values[i].(*ast.BasicLit)
				if !ok || lit.Kind != token.INT {
					continue // 表达式或字符串，不纳入模型
				}
				v, err := strconv.Atoi(lit.Value)
				if err != nil {
					continue
				}
				codes = append(codes, ErrCode{Name: name.Name, Value: v, Doc: doc})
			}
		}
		return false // const 块已处理完，不必再进它的子节点
	})
	return codes, nil
}

func main() {
	src := `package errs

// ErrNotFound 资源不存在
const ErrNotFound = 404

// ErrRateLimit 触发限流
const ErrRateLimit = 429
`
	dir, _ := os.MkdirTemp("", "codegen-")
	defer os.RemoveAll(dir)
	path := filepath.Join(dir, "codes.go")
	if err := os.WriteFile(path, []byte(src), 0o600); err != nil {
		fmt.Println("写样例失败:", err)
		return
	}
	codes, err := ParseCodes(path)
	if err != nil {
		fmt.Println("解析失败:", err)
		return
	}
	for _, c := range codes {
		fmt.Printf("%s = %d  # %s\n", c.Name, c.Value, c.Doc)
	}
}
```

三重防护：断言统一用 comma-ok 而非裸断言；Kind 过滤掉字符串与复杂表达式；隐式继承的常量跳过。解析层对畸形输入必须降级跳过而不是崩溃，因为输入常由别人维护。

### 3.2 渲染层：模板加格式化体检

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"os"
	"text/template"
)

type ErrCode struct {
	Name  string
	Value int
}

const tmplSrc = `// Code generated by gencode; DO NOT EDIT.
package errs

import "fmt"

var registry = map[int]string{
{{- range . }}
	{{ .Value }}: "{{ .Name }}",
{{- end }}
}

// Message 返回错误码对应的可读名称；未知码走兜底，绝不 panic。
func Message(code int) string {
	if name, ok := registry[code]; ok {
		return fmt.Sprintf("%d %s", code, name)
	}
	return fmt.Sprintf("%d unknown", code)
}
`

func Generate(codes []ErrCode) ([]byte, error) {
	tmpl, err := template.New("registry").Parse(tmplSrc)
	if err != nil {
		return nil, fmt.Errorf("模板解析: %w", err)
	}
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, codes); err != nil {
		return nil, fmt.Errorf("模板执行: %w", err)
	}
	// format.Source 既排版又做一次语法体检；产物非法会在这里报错。
	out, err := format.Source(buf.Bytes())
	if err != nil {
		return nil, fmt.Errorf("生成代码不合法: %w", err)
	}
	return out, nil
}

func main() {
	codes := []ErrCode{{Name: "ErrNotFound", Value: 404}, {Name: "ErrRateLimit", Value: 429}}
	b, err := Generate(codes)
	if err != nil {
		fmt.Println("生成失败:", err)
		os.Exit(1)
	}
	fmt.Print(string(b))
}
```

format.Source 是被低估的一环：模板少一个逗号、多一个引号，它当场返回错误，而不是等使用者 go build 才发现。产物头部的 DO NOT EDIT 是约定，vet 与 IDE 都识别它。Message 对未知码返回兜底而非 panic，因为错误码常来自外部输入。

### 3.3 驱动层：幂等落盘

```go
package main

import (
	"bytes"
	"fmt"
	"os"
)

// WriteIfChanged 只在目标内容真的变化时落盘。
func WriteIfChanged(path string, content []byte) (bool, error) {
	old, err := os.ReadFile(path)
	if err == nil && bytes.Equal(old, content) {
		return false, nil
	}
	if err != nil && !os.IsNotExist(err) {
		return false, fmt.Errorf("读取目标: %w", err)
	}
	if err := os.WriteFile(path, content, 0o644); err != nil {
		return false, fmt.Errorf("写入目标: %w", err)
	}
	return true, nil
}

func main() {
	dir, _ := os.MkdirTemp("", "gen-")
	defer os.RemoveAll(dir)
	path := dir + "/zz_generated.go"
	changed, _ := WriteIfChanged(path, []byte("package errs\n"))
	fmt.Println("首次生成:", changed)
	changed, _ = WriteIfChanged(path, []byte("package errs\n"))
	fmt.Println("再次生成:", changed)
}
```

三段拼起来就是完整生成器：解析出模型、Generate 出字节、WriteIfChanged 决定写不写。源码加一行 go:generate 注释即可一键重跑；因为落盘幂等，重复执行既不制造 diff，也不覆盖手改过的同名文件。

## 4. 失败路径与边界条件

输入语法错误由 ParseFile 带位置返回；模板语法错在 Parse 阶段拦截；拼出非法 Go 由 format.Source 提前体检；重复生成靠 bytes.Equal 比对。最隐蔽的是静默降级：跳过解析不了的常量会产出缺项却能编译的代码，跳过时应计数告警。两个常量都写 404 会生成相同 map key，编译器直接报 duplicate key。
